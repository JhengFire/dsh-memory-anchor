# dsh-memory-anchor

> 我给这个包起名 anchor（锚）：记忆的作用是**锚定已经定下来的事**，
> 不让它漂走；而锚会松动、可以回收——这正好对应它的衰减模型。

中文 | [English](README.md)

一个给 DeepSeek Harness 用的记忆插件。它**只**记录代码本身说不清的决策、被否决的方案和踩坑根因，
每条都带一个验证方式；并且会报告记忆在哪些时刻**没帮上忙**。

## 截图

![设置里的记忆锚点分类](https://raw.githubusercontent.com/JhengFire/dsh-memory-anchor/main/docs/images/settings.png)

插件在设置里加一个**记忆锚点**分类：一个开关控制开与关，下方是已保存的记忆，每页 10 条。


### 记忆的范围（scope）

```
[]                    全局，任何位置都能召回
["workspace"]         当前工作区及其所有子目录
["src/surface/**"]    该路径及其子树
["workspace", "src/api/**"]  两者满足其一
```

`workspace` 在检索时按当前工作目录动态解析，**推荐用它代替绝对路径**——
绝对路径写死后，换机器或仓库搬家就失效了。

scope 不匹配不等于消失：只会降权一半，相关度足够高时仍会返回。

## 向量模型（可选，推荐开启）

默认使用**本地哈希向量**：零依赖、可离线，但只认字面。实测同义改写识别率约 20%，
跨语言为 0——「提交前必须跑单测」搜不到「合并代码之前需要执行自动化测试」。

在设置页配置向量模型后，检索能理解语义：

| 用例 | 本地哈希 | 火山方舟 |
|---|---|---|
| 提交前必须跑单测 ⟷ 合并代码之前需要执行自动化测试 | 0.081 | **0.674** |
| 禁止在事务里调外部接口 ⟷ 事务内不要发起跨服务请求 | 0.203 | **0.708** |
| 中文查英文记忆 | 0.000 | **0.604** |

这三个数字是实测值，不是估计。

### 配置

设置 → 记忆锚点 → 向量模型，选服务商、填 API Key，点「测试连接」验证后保存。
API Key 以密码框展示，可切换明文；页面**从不回显完整密钥**，只显示末四位。

### 断网与失败

API 不可用时**不会丢记忆**：降级为本地向量照常写入，并标记待补嵌。
恢复后可用 `memory` 工具的 `reindex` 批量补算：

```
memory action=reindex              # 干跑，只统计要处理多少条
memory action=reindex apply=true   # 真正执行，可断点续跑
```

### 维度

实测 1024 与 2048 的区分度相当（1024 甚至略优），而存储减半，所以默认 1024。

## 安装

需要 DeepSeek Harness `>=0.2.1-rc.3`。

```bash
# 从 npm 安装
dsh plugin add dsh-memory-anchor

# 或从本地检出
git clone https://github.com/JhengFire/dsh-memory-anchor.git
dsh plugin add ./dsh-memory-anchor
```

也可以不用命令行：在 Harness 里打开 **插件 → 添加插件**，指向这个包的目录即可。

插件会注册一个 `memory` 工具，并在设置里加上**记忆锚点**分类。首次使用前无需任何配置。

## 它做什么

Agent 能读代码，但读不出**代码为什么长这样**。哪种方案被否掉了、依据是什么、哪个边界情况已经引发过一次故障——
这些如果不写下来就会消失，然后被重新推导、重新争论，有时还会被重新踩一遍。

这个插件只保留这一小块。它**刻意不存**那些本来就能查到的信息：

| 信息 | 更合适的去处 |
|---|---|
| 符号在哪里、谁在调用 | CodeGraph、LSP |
| 提交历史、某行为什么改 | git |
| 必须始终生效的团队规范 | `AGENTS.md`、skills |
| **为什么做这个决定、否决了什么、根因是什么** | **本插件** |

一旦它开始存别处已经能回答的东西，它就会立刻腐坏。

## `memory` 工具

只有一个工具，通过 `action` 分发，而不是七个独立工具。每个注册的工具都会给每一轮加上一份 schema；
七个工具的成本大约是单个的三倍，而且工具列表一长，模型就越容易"既然有就调一下"——那正是记忆通胀。

| action | 用途 |
|---|---|
| `find` | 按查询检索。先按当前工作目录收敛范围。 |
| `add` | 记录 `decision`、`constraint`、`gotcha` 或 `rejected`。其余一律拒绝。 |
| `verify` | 报告某条记忆是否仍然成立。失败即标为过期。 |
| `resolve` | 裁决两条记忆之间的冲突：保留一条，或两条并列待确认。 |
| `use` / `miss` | 报告某条记忆是否真的帮上了忙。这是衰减的唯一依据。 |
| `stats` | 库健康度：有多少条缺少验证方式。 |
| `eval` | 记忆在哪些地方没帮上忙，按失败类型归类。 |

## 为什么它"轻"

- **默认不注入任何内容。** 系统提示只多一行用法说明，从不包含记忆正文。不调用工具的那一轮，成本为零。
- **写入有闸门。** 只有四种情况能创建条目：一次决策被拍板、一个方案带着理由被否决、一个根因被找到、
  一个错误认知被纠正。对话不会在结束时被自动总结成记忆——噪音主要就是从那里来的。
- **每条都能被证伪。** `verify` 里存一条可执行的检查。读到一条记忆时，你可以花很小的代价确认它，
  而不是相信它。
- **衰减由结果驱动，不由时间驱动。** `use` 和 `miss` 决定谁留下。用过一次且仍然正确的东西，
  不会仅仅因为"老了"就被淘汰。
- **一个文件，无服务。** 记录存在一个存储域里：可读、有 schema 校验、写入即持久的 JSON 单元。
  没有守护进程，没有向量数据库，没有网络调用。

## 冲突从不被悄悄解决

两句话可以共享几乎每一个词却互相矛盾——"生产环境禁止使用 SNAPSHOT"和"生产环境允许使用 SNAPSHOT"。
相似度**分不清赞同与否定**，它只能告诉你这两句在讲同一件事。

所以插件选择**问**。检测到冲突就拒绝写入，把双方都摆出来，只有 `resolve` 能裁决。在那之前，
两条都保持"待确认"，每次检索都会标出冲突。因为一条假装已定、实际未定的记忆，比没有记忆更糟。

纯粹的更正——比如日期从"昨天"改成"前天"——会自动应用，旧条目保留为"已取代"，让改动可追溯。

## 报告自己在哪些地方失败

七类失败，全部从记录下来的工具调用中判定，不依赖自我上报：

| | 失败类型 | 判定信号 |
|---|---|---|
| F1 | 未召回 | 检索为空，几分钟后又补写了同一主题 |
| F2 | 召回但无用 | 返回了结果，之后没有任何 `use` |
| F3 | 验证失败 | `verify` 报告它已不成立 |
| F4 | 决策重开 | 同一组标签下出现第二条生效中的决策 |
| F5 | 冲突 | 两条条目互相矛盾 |
| F6 | 任务未完成 | 可选，需要外部结果信号 |
| F7 | 反馈缺失 | 返回了结果，既没被采用也没被否决 |

F7 单独列出，因为它会让 F2 失效。如果某个会话从头到尾不报告任何反馈，
"召回但未被使用"就无法和"召回了但没人说"区分开。F7 高的时候，报告会**明说这一点**，
而不是悄悄吐出一堆数字。

## 设置页

插件在设置里加一个**记忆锚点**分类：

- 一个开关。关闭后 `find`/`add`/`verify`/`resolve`/`use`/`miss` 会被拒绝；
  但 `stats`、`eval` 以及本页列表仍然可用。**关掉记忆，不等于让你失去查看已存内容的途径。**
- 已保存的记忆，每页 10 条，最新的在前，每条显示类型、状态标记、`verify` 命令和路径范围。

开关会写回 profile patch，重启后仍然有效。

## 配置

所有项都可以在 profile patch 里改，升级不会丢。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `limit` | `5` | `find` 返回的结果条数 |
| `staleDays` | `180` | 多少天未验证后转为过期 |
| `retireMisses` | `3` | 连续多少次未采用（且零采纳）后归档 |
| `conflictWindowSec` | `1800` | 在此窗口内的反转视为可立即判定 |
| `evalEnabled` | `true` | 是否记录用于失败报告的使用事件 |
| `polarityPairs` | `[]` | 额外极性词对，每行 `肯定词=否定词` |
| `promptSection` | `true` | 是否在系统提示里加那一行用法说明 |

## 已知限制

- 检索是**词面相似度**，不是语义理解。它能匹配同语言、共享字面的内容；但中英跨语言匹配不了，
  完全没有共同字符的同义表达也匹配不了。`verify` 和路径范围之所以存在，正是因为这一点。
- 冲突判定要求对立双方在剥掉极性词之后仍有共同主题。改写幅度很大的矛盾可能漏判。
